# 6. RF & Wireless

Key fobs, TPMS, BLE phone-as-a-key, cellular telematics, V2X.

## Try it first

### Sniff TPMS with rtl_433 ($25 SDR, zero setup)

Every car on the road broadcasts TPMS (tire pressure) on 315 or 433 MHz — unencrypted, with a unique sensor ID per tire. You can passively track vehicles.

```bash
# Plug in RTL-SDR, run:
rtl_433 -f 315M -R 60    # US: 315 MHz, protocol 60 = common TPMS

# Or scan all known protocols:
rtl_433

# Example output:
# time: 2026-09-17 14:22:03
# model: Toyota   TPMS
# id:    0xAB12CD34
# pressure_PSI: 32.5
# temperature_C: 28
# battery_ok: 1

# Every tire has a unique ID. Same IDs = same car.
# Track a car by its TPMS without ever seeing the plate.
```

**What you're seeing:** TPMS is a broadcast protocol with zero authentication. The sensor IDs are static and unique. This is a real privacy issue and a useful recon tool during assessments.

### Sniff BLE phone-as-a-key with Sniffle

Modern vehicles use BLE for phone-as-a-key (Tesla, BMW, Hyundai, etc.). Sniffle captures the BLE advertisements and connection events.

```bash
# Flash Sniffle firmware to a TI CC26x2 Launchpad (~$30)
# (follow Sniffle README for flashing instructions)

# Sniff all BLE advertisements on channel 37:
python3 sniffle_hw.py -a

# Follow a specific device (once you know its address):
python3 sniffle_hw.py -t AA:BB:CC:DD:EE:FF -o capture.pcap

# Open in Wireshark — filter: btle
# You'll see:
#   ADV_IND packets (device advertising)
#   CONNECT_IND (phone initiating connection)
#   LL_ENC_REQ / LL_ENC_RSP (encryption setup)
#   ATT Read/Write (GATT operations — this is where
#   the unlock command lives)
```

**What you're seeing:** the BLE exchange between a phone and a vehicle. Research targets: is the BLE relay-resistant? Can you capture and replay the unlock sequence? Is the GATT characteristic for unlock properly authenticated?

### Capture a key fob signal with URH

```bash
# Start URH with your RTL-SDR or HackRF
urh

# 1. Go to the "Record" tab
# 2. Set frequency: 315 MHz (US) or 433.92 MHz (EU)
# 3. Set sample rate: 2M
# 4. Press your key fob lock/unlock near the antenna
# 5. You'll see the signal appear as a waveform

# URH auto-detects modulation (ASK/OOK for most key fobs)
# Switch to "Analysis" tab to see the decoded bits
# Switch to "Interpretation" tab to identify the protocol

# For rolling code systems: capture multiple presses and
# compare — the code changes each time. That's what makes
# RollJam interesting (capture + jam to prevent the car
# from receiving it, then you hold a valid unused code).
```

**What you're seeing:** the raw RF signal your key fob transmits. Older fixed-code systems replay trivially. Rolling code systems require more sophisticated attacks (RollJam, RollBack). This is receive-only and legal on your own devices.

## Getting started

1. RTL-SDR + URH — receive-only, capture signals from your own devices
2. rtl_433 — passive decode of TPMS and other ISM band signals in your environment
3. Sniffle on a CC26x2 Launchpad (~$30) — BLE sniffing for phone-as-a-key research
4. Flipper Zero for quick RF recon, then HackRF when you need TX capability
5. Transmitting requires understanding local regulations — start receive-only
